# 05 — Host Adapters (Middleware)

Source pins for everything below:

- Spec: [`../spec/docs/draft-arcp-02.1.md`](../../../spec/docs/draft-arcp-02.1.md), in particular §4 (WebSocket mandatory, JSON text frames, one transport per session) and §11 (W3C `traceparent` rides on `extensions["x-vendor.opentelemetry.tracecontext"]`).
- v1.1 deltas: [`01-spec-delta.md`](./01-spec-delta.md) §11 row (new OTel span attrs `arcp.lease.expires_at`, `arcp.budget.remaining`).
- SDK audit: [`02-current-audit.md`](./02-current-audit.md) §2 (the four transports under [`src/arcp/transport/`](../../../python-sdk/src/arcp/transport/) are **Salvage** — base interface, `MemoryTransport`, `StdioTransport`, and the `websockets`-library-backed `WebSocketTransport` survive verbatim). Middleware home is [`arcp/middleware/`](../../../python-sdk/src/arcp/) — already implied by audit §2 row "OTel span attrs … `arcp/middleware/otel/`".
- Library picks: [`03-libraries.md`](./03-libraries.md) §2 commits the SDK's default standalone WS server to the `websockets` library and explicitly notes "the server-side WS upgrade lives inside the SDK, not behind a user-provided ASGI app" so backpressure measurement against `transport.get_write_buffer_size()` is available for §6.5. The adapters in this document are the **co-mount** path for consumers whose existing service already terminates HTTP/WS in a host framework; they accept that §6.5 backpressure detection on that path falls back to seq-lag inference only (the host framework owns the write buffer). The default `arcp serve` path uses 03 §2's in-tree server and is not an adapter.
- TS reference tree: [`../typescript-sdk/packages/middleware/`](../../../typescript-sdk/packages/middleware/) with subpackages `node/`, `express/`, `fastify/`, `hono/`, `bun/`, `otel/`.

Library commitments that ride into every adapter below (sourced from 03; this file is the host-adapter half of those picks):

- **WebSocket library (default standalone server):** `websockets>=13` (03 §2). Lives in `arcp.transport.websocket` — *not* an adapter; it is the SDK's own server primitive and its own client.
- **WebSocket library (ASGI co-mount path):** the ASGI server's own WS implementation. uvicorn ships `wsproto` and `websockets` backends; hypercorn ships its own; the adapter never imports `websockets` directly because the WS handshake has already happened by the time ASGI hands us the scope.
- **WebSocket library (aiohttp co-mount path):** `aiohttp.web.WebSocketResponse`. aiohttp is not ASGI and uses its own WS stack.
- **OTel propagation:** `opentelemetry-api>=1.27,<2` (03 §7, API-only — no `-sdk` dependency, consumers configure the tracer provider themselves). The Python API surface lives under `opentelemetry.trace` and `opentelemetry.propagate`.
- **Module tree:** `arcp.middleware.asgi`, `arcp.middleware.aiohttp`, `arcp.middleware.otel`. Each is a leaf module (not a sub-package), parallel to the TS sub-package names but trimmed because Python doesn't fan out one host adapter per framework — see §2.

## 1. The shipped adapter set

### 1.1 `arcp.middleware.asgi`

The Python ASGI 3.0 protocol (PEP 3333-style but async) defines a single `websocket` scope shared by Starlette, FastAPI (which is Starlette underneath), Litestar, Quart, BlackSheep, and Sanic-ASGI — the WS handshake events `websocket.connect` / `websocket.receive` / `websocket.send` / `websocket.disconnect` are identical across all of them by spec, so the host adapter is one module, not four. The seam is a single ASGI callable that the host app mounts at `/arcp` via its native router (Starlette `Route` / FastAPI `add_api_websocket_route` / Litestar `Router(route_handlers=[...])`); the adapter accepts the WS, constructs the `Transport`-shaped object (per [`src/arcp/transport/base.py:18`](../../../python-sdk/src/arcp/transport/base.py#L18) `Transport.send/recv/close`) over `await scope_receive()` / `await scope_send()`, and calls `await runtime.accept(transport)` — the same single-entry seam the TS `attachArcpUpgrade(server, {onTransport})` in [`typescript-sdk/packages/middleware/node/src/index.ts:35`](../../../typescript-sdk/packages/middleware/node/src/index.ts#L35) provides. DNS-rebind / `Host`-header protection lives before the `websocket.accept` send, against `scope["headers"]` (a list of `(name_bytes, value_bytes)` tuples per ASGI WS spec); rejection sends `{"type": "websocket.close", "code": 1008}` and never accepts. This mirrors the TS Node adapter's `hostHeaderAllowed` check at [`typescript-sdk/packages/middleware/node/src/index.ts:85`](../../../typescript-sdk/packages/middleware/node/src/index.ts#L85), executed before `wss.handleUpgrade` (which is the moral equivalent of `websocket.accept`). The API line: `def arcp_asgi_app(runtime: ARCPRuntime, *, allowed_hosts: Sequence[str] | None = None) -> ASGIApp`, where the returned callable matches the ASGI 3 signature `async def app(scope, receive, send) -> None` and is mounted by the host framework's router (Starlette: `app.add_websocket_route("/arcp", arcp_asgi_app(runtime, allowed_hosts=["localhost"]))`). No framework imports — `from starlette.websockets import WebSocket` would couple the adapter to one framework's helper class; the adapter speaks raw ASGI scope events and runs unmodified under FastAPI, Litestar, and Quart. §6.5 backpressure caveat (from [`03-libraries.md`](./03-libraries.md) §2): the ASGI WS write buffer is owned by the ASGI server (uvicorn/hypercorn), not visible through the ASGI 3 send protocol, so on this path the runtime's §6.5 detection falls back to seq-lag inference from `session.ack` only (`SessionContext.recordAck` per the TS reference); `get_write_buffer_size`-style measurement is unavailable. Operators who need socket-level backpressure deploy the in-tree `websockets`-backed server (03 §2) instead of this adapter.

### 1.2 `arcp.middleware.aiohttp`

`aiohttp.web` is not ASGI — its `Application` has its own request lifecycle and its own `WebSocketResponse` class — so the generic ASGI adapter does not cover it, and a one-paragraph adapter is justified by ecosystem usage (PyPI download metrics put `aiohttp` second only to Starlette among async Python HTTP servers; large existing deployments at Cloudflare, Yandex, and the Python core team's `python-build-standalone` build infra). The seam is an `aiohttp` route handler: `async def _handler(request: web.Request) -> web.WebSocketResponse`. It instantiates `ws = web.WebSocketResponse(heartbeat=None)` (no aiohttp-level ping; ARCP heartbeats are §6.4-level), calls `await ws.prepare(request)` (the WS upgrade), wraps it in a `Transport` adapter whose `send` calls `await ws.send_str(json.dumps(envelope))` and whose `recv` consumes `async for msg in ws:` (filtering `msg.type == WSMsgType.TEXT`), and hands the transport to `await runtime.accept(transport)`. Compare against TS Fastify [`typescript-sdk/packages/middleware/fastify/src/index.ts:46`](../../../typescript-sdk/packages/middleware/fastify/src/index.ts#L46) — Fastify likewise lets Node's underlying `http.Server` do the upgrade and only attaches at the upgrade-event seam; aiohttp's `WebSocketResponse.prepare` is the equivalent attach point. DNS-rebind / Host-header protection lives in the handler entry, against `request.headers.get("Host")`, before `ws.prepare`; rejection returns `web.Response(status=403, text="Forbidden: Host header not allowed")`. API line: `def arcp_aiohttp_handler(runtime: ARCPRuntime, *, allowed_hosts: Sequence[str] | None = None) -> Callable[[web.Request], Awaitable[web.WebSocketResponse]]`, registered by the host app as `app.router.add_get("/arcp", arcp_aiohttp_handler(runtime, allowed_hosts=["localhost"]))`. §6.5 backpressure caveat (from [`03-libraries.md`](./03-libraries.md) §2, which calls out aiohttp specifically — "aiohttp … buries the buffer behind its own send queue"): on this path the runtime's §6.5 detection falls back to seq-lag inference from `session.ack` only; operators wanting socket-level write-buffer measurement deploy the in-tree `websockets`-backed server instead.

### 1.3 `arcp.middleware.otel`

Spec §11 with the v1.1 additions in [`01-spec-delta.md`](./01-spec-delta.md) row "OTel span attrs `arcp.lease.expires_at`, `arcp.budget.remaining`" is the conformance target. The adapter wraps any `Transport` (`arcp.transport.base.Transport` per [`src/arcp/transport/base.py:18`](../../../python-sdk/src/arcp/transport/base.py#L18)) so each `send` and `recv` produces a span, mirroring the TS contract at [`typescript-sdk/packages/middleware/otel/src/index.ts:57`](../../../typescript-sdk/packages/middleware/otel/src/index.ts#L57) `withTracing(inner, {tracer})`. W3C `traceparent` round-trips via the envelope's `extensions["x-vendor.opentelemetry.tracecontext"]` slot — the exact key string is preserved from TS [`otel/src/index.ts:48`](../../../typescript-sdk/packages/middleware/otel/src/index.ts#L48) `OTEL_EXTENSION_NAME` and matches spec §11's vendor-namespaced extension convention from §15; on `send` the active context is injected via `opentelemetry.propagate.inject(carrier, context=trace.set_span_in_context(span))`, on `recv` it is extracted with `opentelemetry.propagate.extract(carrier)` and used as the parent for the inbound span. One span per envelope (kind `PRODUCER` on `send`, `CONSUMER` on `recv`, span name `arcp.send <type>` / `arcp.recv <type>`); attribute names from the TS `extractAttributes` helper are preserved verbatim so traces stitch across SDKs without renormalization. The propagator is consumer-controlled — the adapter accepts a `tracer: opentelemetry.trace.Tracer` parameter rather than calling `trace.get_tracer(__name__)` internally, matching TS [`otel/src/types.ts:6`](../../../typescript-sdk/packages/middleware/otel/src/types.ts#L6) `WithTracingOptions.tracer`. API line: `def with_tracing(inner: Transport, *, tracer: trace.Tracer, send_span_name: Callable[[dict], str] | None = None, recv_span_name: Callable[[dict], str] | None = None) -> Transport`. The wrapped transport is a drop-in for the unwrapped one and is composable with §1.1 / §1.2: `runtime.accept(with_tracing(asgi_transport, tracer=tracer))`.

## 2. Rejected adapters

- **`flask` / `flask-sock`**: Flask's WSGI core does not handle the WS upgrade; production deployments need `flask-sock` (which wraps `simple-websocket`) or `Flask-SocketIO` (which is socket.io, a different protocol). Both combinations are rare for new async work (PyPI shows `flask-sock` at <2 % the download volume of `starlette`), and `flask-sock`'s blocking-handler model fights the ARCP runtime's asyncio expectations — wiring would require `asgiref.sync.async_to_sync` per frame, which destroys the §8.3 sequence-ordering guarantee on bursts.
- **`tornado`**: declining ecosystem (the Tornado project itself moved its examples to `asyncio` interop years ago, and there is no Tornado-native v1.1+ HTTP library being adopted in 2026). Anyone on Tornado in 2026 is either on legacy infra (use the stdlib WS server in the conformance harness, not a middleware) or is migrating to ASGI (use §1.1).
- **`django` / `django-channels`**: Django Channels routes ASGI under the hood — the consumer base class `AsyncWebsocketConsumer` is sugar over the same `websocket.receive` / `websocket.send` events §1.1 already targets. The audience of ARCP-server deployments that *must* run inside a Channels routing table is small (ARCP is a runtime control plane, not a request/response surface co-mounted with Django views), and §1.1 plus a one-line `re_path("ws/arcp", arcp_asgi_app(runtime))` in `routing.py` covers the rare case without a maintained adapter.
- **One adapter per ASGI framework (separate Starlette, FastAPI, Litestar, Quart adapters)**: ASGI 3 specifies the `websocket` scope identically across all four (PEP-style governance: any divergence is a framework bug, not an ARCP extension point). Shipping four parallel modules quadruples the maintenance surface (each gets its own typing imports, its own CI matrix entry, its own version-skew window with the host framework's release cadence) for zero behavioral gain. The TS reference fans out across Node/Express/Fastify/Hono *because Node's HTTP server forces it* — Express, Fastify, and Hono share `http.Server` but expose different mount APIs ([`express/src/index.ts:63`](../../../typescript-sdk/packages/middleware/express/src/index.ts#L63), [`fastify/src/index.ts:41`](../../../typescript-sdk/packages/middleware/fastify/src/index.ts#L41), [`hono/src/index.ts:58`](../../../typescript-sdk/packages/middleware/hono/src/index.ts#L58)), and they delegate the upgrade to the shared `@arcp/node` adapter [`node/src/index.ts:35`](../../../typescript-sdk/packages/middleware/node/src/index.ts#L35). Python's ASGI 3 already is the shared "node adapter"; the host frameworks are the thin wrappers, the other direction from TS.

## 3. Optional defensible adds

- **`arcp.middleware.litestar`**: do not ship. Litestar's `WebSocket` class wraps the same ASGI events §1.1 handles; the `websocket_listener` decorator's stream surface is sugar over `async for ... in websocket.iter_data()`, and a Litestar deployment can mount `arcp_asgi_app(runtime)` under `litestar.Router(path="/arcp", route_handlers=[asgi(arcp_asgi_app(runtime))])` in one line. There is no Litestar-specific seam (auth guards, dependency injection per-WS, response middleware) the ARCP adapter needs to use — ARCP authentication is per-§6.1 bearer-token verification inside the runtime, not at the framework's middleware layer.
- **`arcp.middleware.quart`**: do not ship. Quart's `@app.websocket("/arcp")` decorator builds the same ASGI WS scope; `Quart.asgi_app` is canonical ASGI 3. The §1.1 adapter mounts directly as `app.add_websocket_route` or, on older Quart versions, `app.asgi_app.add_websocket("/arcp", arcp_asgi_app(runtime))`.

Default: the generic ASGI adapter is enough. The bar to ship a framework-specific module is "the ASGI scope alone cannot express the framework's WS contract" — which is currently empty.

## 4. WS-upgrade attachment patterns

- **`arcp.middleware.asgi`**: lifespan is handled by the host framework; the adapter itself does not register lifespan hooks. The ASGI callable receives `scope["type"] == "websocket"` and runs the upgrade with `await send({"type": "websocket.accept"})` after the host-header check passes; the `Transport` object is constructed against the `(scope, receive, send)` triple, with `send_envelope` calling `await send({"type": "websocket.send", "text": json.dumps(envelope)})` and `recv_envelope` calling `event = await receive()` then dispatching on `event["type"]` (text → return JSON, `websocket.disconnect` → raise `TransportClosed`). Once accepted, the adapter calls `await runtime.accept(transport)` and stays in that coroutine until the runtime returns; the framework's router treats that as the long-lived WS handler, exactly the shape TS `attachArcpUpgrade` produces at [`typescript-sdk/packages/middleware/node/src/index.ts:64`](../../../typescript-sdk/packages/middleware/node/src/index.ts#L64) (`wss.handleUpgrade(req, socket, head, (ws) => { ... onTransport(transport, req); })`). DNS-rebind / Host-header protection lives **before** the `websocket.accept` send — once the WS is accepted the browser may already have committed to the cross-origin write. Concretely: parse `Host:` from `scope["headers"]`, strip port, compare against `allowed_hosts`; on mismatch send `{"type": "websocket.close", "code": 1008}` and return.
- **`arcp.middleware.aiohttp`**: the upgrade happens inside the route handler when `await ws.prepare(request)` returns. The `Transport` adapter wraps `ws` (a `web.WebSocketResponse`): `send` calls `await ws.send_str(json.dumps(envelope))`; `recv` pulls from `async for msg in ws:` (a single internal `asyncio.Queue`), raising `TransportClosed` on `WSMsgType.CLOSE` / `CLOSED` / `ERROR` and on the iterator's natural end. Compare against TS Fastify [`fastify/src/index.ts:46`](../../../typescript-sdk/packages/middleware/fastify/src/index.ts#L46) — Fastify's `app.server` is what's wired, not Fastify's request pipeline, because the upgrade fires before the pipeline; aiohttp's analogue is that `WebSocketResponse.prepare` short-circuits the normal response flow and seizes the underlying socket for WS framing. DNS-rebind / Host-header protection lives at the **handler entry**, before `ws.prepare`: read `request.headers.get("Host")`, strip port, compare against `allowed_hosts`; on mismatch return `web.Response(status=403)` without ever calling `prepare`.

## 5. OTel adapter parity

The wire-level rule, stated once: the **client** writes `traceparent` (and optionally `tracestate`) into `envelope.extensions["x-vendor.opentelemetry.tracecontext"]` on every outbound envelope where a trace is active (notably `session.hello` and every `job.submit`, but the wrapper is uniform — it instruments the `Transport.send` seam, so it covers all 17 v1.1 envelope types including `session.ack`, `session.ping`, `job.subscribe`, and `result_chunk`-bearing events). The **runtime** reads it back the same way on inbound. This propagation is the responsibility of `arcp.middleware.otel.with_tracing`, **never** of `arcp.core` — the core SDK does not depend on `opentelemetry-api`.

| TS attribute ([`otel/src/index.ts:139`](../../../typescript-sdk/packages/middleware/otel/src/index.ts#L139)) | Python adapter attribute | Source on the envelope | v1.0 / v1.1 |
| ---------- | ---------- | ---------- | ---------- |
| `arcp.direction`              | `arcp.direction`              | constant `"in"` / `"out"` per call site | v1.0 |
| `arcp.type`                   | `arcp.type`                   | `envelope["type"]` | v1.0 |
| `arcp.id`                     | `arcp.id`                     | `envelope["id"]` | v1.0 |
| `arcp.session_id`             | `arcp.session_id`             | `envelope["session_id"]` | v1.0 |
| `arcp.job_id`                 | `arcp.job_id`                 | `envelope["job_id"]` | v1.0 |
| `arcp.trace_id`               | `arcp.trace_id`               | `envelope["trace_id"]` | v1.0 |
| `arcp.event_seq`              | `arcp.event_seq`              | `envelope["event_seq"]` (numeric) | v1.0 |
| `arcp.agent`                  | `arcp.agent`                  | `payload["agent"]` (`name@version` post-§7.5) | v1.0 |
| `arcp.lease.capabilities`     | `arcp.lease.capabilities`     | comma-joined keys of `payload["lease"]` or `payload["lease_request"]` | v1.0 |
| `arcp.lease.expires_at`       | `arcp.lease.expires_at`       | `payload["lease_constraints"]["expires_at"]` (ISO 8601 Z) — spec §9.5 / §11 | **v1.1** |
| `arcp.budget.remaining`       | `arcp.budget.remaining`       | `json.dumps(payload["budget"])` preserving per-currency totals — spec §9.6 / §11 | **v1.1** |

String-equality across SDKs is the load-bearing property here: a span-name pivot or an attribute-name normalization on either side would break cross-SDK distributed tracing in collectors that join on these keys.

## 6. CLI-runnable WS server helper

The default `arcp serve` path is *not* an adapter — it is the in-tree `websockets`-backed server in `arcp.transport.websocket` ([`02-current-audit.md`](./02-current-audit.md) §2 row marks it Salvage; [`03-libraries.md`](./03-libraries.md) §2 commits to it), wired by `arcp.cli` ([`03-libraries.md`](./03-libraries.md) §10) and parallel to the TS `serveArcp` in [`typescript-sdk/packages/middleware/bun/src/index.ts:51`](../../../typescript-sdk/packages/middleware/bun/src/index.ts#L51). `arcp.middleware.aiohttp` additionally ships a convenience helper because aiohttp owns its own event loop and HTTP server, so a one-line co-mount helper saves enough boilerplate to ship: `async def serve_arcp_aiohttp(runtime: ARCPRuntime, *, host: str = "127.0.0.1", port: int = 7777, path: str = "/arcp", allowed_hosts: Sequence[str] | None = None) -> None`. It builds an `aiohttp.web.Application`, registers the §1.2 handler at `path`, and runs `web.run_app` (or, for in-process tests, `AppRunner` + `TCPSite`). `arcp.middleware.asgi` ships no such helper — the ASGI adapter is mounted on the user's chosen ASGI server (uvicorn/hypercorn), so a `serve_arcp_asgi` would just re-export `uvicorn.run` and would obscure the ASGI server pick that consumers already make themselves.
