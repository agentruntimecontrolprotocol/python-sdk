## 1. Stack pick + dependencies

Pinned runner stack matches [`03-libraries.md`](03-libraries.md) §11:

- `pytest>=8`
- `pytest-asyncio>=0.24` — the **single** async driver. `anyio`'s pytest
  plugin is rejected at the same point [`03-libraries.md`](03-libraries.md)
  §4 rejects `anyio` itself: the audit's §4 cancellation seam pins on
  `asyncio.CancelledError` semantics that `anyio.CancelScope` papers over.
  `asyncio_mode = "auto"` is already set in
  [`pyproject.toml`](../../pyproject.toml) `[tool.pytest.ini_options]`.
- `hypothesis>=6.112` — property tests for the rows §3 of this document
  names below.
- `pytest-cov>=5` — coverage gate.

Justified additions to the dev group:

- **`pytest-randomly>=3.15` — yes.** The state-machine layer
  (§2 below, `tests/state/`) exercises the
  [`02-current-audit.md`](02-current-audit.md) §3 H-risk row (subscriber
  fan-out seq space); a fixture leak between two tests in that layer
  would let one subscriber's `event_seq` counter contaminate another and
  silently produce the same misbehavior the H-risk row describes.
  `pytest-randomly` flushes the leak the moment it appears in CI, and
  the cost is zero (it does not change wall-clock).
- **`freezegun>=1.5` — no.** The audit explicitly recommends clock
  injection on `validateLeaseOp(now=…)` ([`02-current-audit.md`](02-current-audit.md)
  §3 row "`validateLeaseOp` accepting `now` for clock injection"), and
  Phase 4 will expose that seam on `_runtime/lease.py`. With the seam in
  place, `freezegun` patches `time.time()` for tests that never call it.
  Lease-expiry tests pass `now=` explicitly; the heartbeat-loss test
  uses a `MemoryTransport` event clock (§4 below), not wall time. Adding
  `freezegun` would compete with the seam and split the project across
  two clock-control idioms.
- **`dirty-equals>=0.8` — yes.** The envelope round-trip assertions in
  `tests/unit/envelope/` compare emitted envelopes whose `id` is a ULID
  generated by `python-ulid` ([`03-libraries.md`](03-libraries.md) §6)
  and whose `event_seq` is allocated by the runtime. `dirty-equals`'
  `IsULID()` / `IsPositiveInt()` / `IsNow(delta=...)` matchers let the
  assertions stay tight on the spec-defined fields without round-tripping
  through `model_dump` with field exclusions, which loses the
  "unknown-field tolerance" verification the assertion is supposed to
  cover (§5.1).
- **`pytest-timeout>=2.3` — yes.** The async cancellation paths
  ([`02-current-audit.md`](02-current-audit.md) §4 first bullet) can
  deadlock under regression — a stuck `TaskGroup.__aexit__` with a child
  that never cancels would hang CI indefinitely. `pytest-timeout`'s
  per-test budget (`@pytest.mark.timeout(5)` on the suite, override per
  test) bounds the failure to the offending test instead of the job.

Dev group diff (against [`pyproject.toml`](../../pyproject.toml) and
[`03-libraries.md`](03-libraries.md) §16): add `hypothesis>=6.112`,
`pytest-randomly>=3.15`, `dirty-equals>=0.8`, `pytest-timeout>=2.3`. No
other additions.

## 2. Layered plan

Five layers under `tests/`. Each layer is a directory; tests inside it
import from the corresponding source tree only.

### 2.1. `tests/unit/envelope/` — Envelope unit

Source under test: `src/arcp/_envelope.py`, `src/arcp/_ids.py`. Spec
basis: §5.1 (8-field envelope, `arcp: "1"`, ULID/UUIDv7 `id`, 32-hex
`trace_id`, unknown-field rule).

Test files:

- `test_envelope_constants.py` — `arcp` field MUST equal `"1"`; rejects
  `"1.0"`, `"2"`, missing field, non-string. This is the regression for
  the [`02-current-audit.md`](02-current-audit.md) §1 row "Envelope
  constant" (today's value is `"1.0"`); the test exists to fail loudly
  if anyone reverts.
- `test_envelope_required_fields.py` — `id`, `type`, `payload` REQUIRED
  on every envelope; `session_id` REQUIRED post-welcome (one parametrize
  per post-welcome verb listed in
  [`typescript-sdk/CONFORMANCE.md`](../../../typescript-sdk/CONFORMANCE.md)
  §5); `event_seq` REQUIRED on `job.event` / `job.result` / `job.error`
  and FORBIDDEN on `session.hello` / `session.welcome` / `session.ping`
  / `session.pong` / `session.ack`.
- `test_envelope_id_format.py` — `id` matches ULID (Crockford base32,
  26 chars) or UUIDv7 (`xxxxxxxx-xxxx-7xxx-yxxx-xxxxxxxxxxxx`). Driven by
  [`03-libraries.md`](03-libraries.md) §6 (`python-ulid`); the test
  accepts both forms because the spec accepts both.
- `test_envelope_trace_id_format.py` — W3C `trace_id` is exactly 32
  lowercase hex chars; `00000000000000000000000000000000` is rejected
  per W3C TraceContext; missing field is accepted (`trace_id` is
  OPTIONAL per §5.1).
- `test_envelope_unknown_fields.py` — passes through unknown top-level
  fields on inbound deserialization (§5.1 lead-in + §5 lead-in of
  v1.1); rejects them on **construction** by the Python type model
  (the SDK does not author unknown fields).
- `test_envelope_roundtrip.py` — `from_wire(to_wire(env)) == env` for
  every typed envelope under `_messages/*`. The Hypothesis form lives in
  §3.

### 2.2. `tests/unit/messages/` — Message unit

Source under test: `src/arcp/_messages/session.py`,
`src/arcp/_messages/execution.py`, and the registry
`src/arcp/_messages/__init__.py`. Spec basis: §6, §7, §8.2, §9.

One module per spec section so test failure traces back to a spec
section by filename:

- `test_session_hello.py` — §6.2. `client`, `auth.scheme=="bearer"` +
  `auth.token`, `capabilities.encodings`, `capabilities.features`
  (string list). v1.1 client sends features array; v1.0 client omits
  it. Both forms are accepted by `SessionHelloPayload`.
- `test_session_welcome.py` — §6.2. `runtime`, `resume_token`,
  `resume_window_sec`, `heartbeat_interval_sec` (OPTIONAL),
  `capabilities.features`, `capabilities.agents` accepts both
  `list[str]` (v1.0 shape) and `list[{name, versions, default?}]` (v1.1
  rich shape, conditioned on `agent_versions`). This is the test
  [`01-spec-delta.md`](01-spec-delta.md) §3 calls "the entire
  compatibility hinge".
- `test_session_heartbeat.py` — §6.4. `session.ping` body
  `{nonce, sent_at}`; `session.pong` body `{ping_nonce, received_at}`.
  `sent_at` / `received_at` are ISO 8601 UTC with `Z`.
- `test_session_ack.py` — §6.5. `session.ack.payload.last_processed_seq`
  is non-negative int. Construction with a negative value raises
  `INVALID_REQUEST` per the runtime; the message-layer test asserts the
  pydantic-level rejection.
- `test_session_list_jobs.py` / `test_session_jobs.py` — §6.6.
  `filter.status ⊆ {pending, running, success, error, cancelled,
  timed_out}`, `filter.agent` (bare name or `name@version`),
  `filter.created_after` ISO 8601, `limit` 1..1000, `cursor` opaque
  string. Response: `request_id` echoes envelope `id`; `jobs[*]` matches
  the `JobListEntry` shape in
  [`typescript-sdk/CONFORMANCE.md`](../../../typescript-sdk/CONFORMANCE.md)
  §6.6.
- `test_session_bye.py` — §6.7. `reason` REQUIRED, `code?` OPTIONAL.
- `test_session_error.py` — §13.7 / §12. `code` REQUIRED, `message`
  REQUIRED, `retryable` REQUIRED. Used for `AGENT_VERSION_NOT_AVAILABLE`
  (§7.5) — the only v1.1 error code carried as a `session.error` rather
  than a `job.error`.
- `test_job_submit.py` — §7.1, §7.5, §9.5. `agent` is `name` or
  `name@version`; `lease_request` is `{capability: pattern[]}`;
  `lease_constraints.expires_at` ISO 8601 UTC with `Z`, MUST be future
  (relative to a `now=` injection point per the
  [`02-current-audit.md`](02-current-audit.md) §3 clock-injection row);
  `idempotency_key` 1..256 chars; `max_runtime_sec` 1..86400.
- `test_job_accepted.py` — §7.1. Echoes `lease`, `lease_constraints?`,
  `budget?`, `accepted_at`, `trace_id?`, `parent_job_id?`,
  `delegate_id?`. `budget` is `{currency: decimal}` per §9.6.
- `test_job_cancel.py` — §7.4. `reason` REQUIRED, `code?` OPTIONAL.
- `test_job_subscribe.py` / `test_job_subscribed.py` /
  `test_job_unsubscribe.py` — §7.6. `job_id`, optional `from_event_seq`,
  optional `history` (default `false`). Response shape from
  [`typescript-sdk/CONFORMANCE.md`](../../../typescript-sdk/CONFORMANCE.md)
  §7.6.
- `test_job_event_kinds.py` — §8.2. Parametrized over the ten reserved
  kinds (`log`, `thought`, `tool_call`, `tool_result`, `status`,
  `metric`, `artifact_ref`, `delegate`, `progress`, `result_chunk`),
  validating each `body` shape against the spec. `progress` body §8.2.1
  with non-negative `current` and `current <= total` when `total`
  present. `result_chunk` body §8.4 with `encoding ∈ {utf8, base64}`,
  `chunk_seq >= 0`, `more` REQUIRED. `metric` body for §9.6 cost
  reporting: `name` starts with `cost.`, `unit` matches a currency,
  negative `value` rejected.
- `test_job_result.py` / `test_job_error.py` — §7.3, §8.4. `job.result`
  carries `final_status ∈ {success, cancelled, timed_out}` for v1.0;
  v1.1 adds `result_id?` + `result_size?` (only set when streamed; never
  set alongside an inline `result` field per §8.4 "MUST NOT mix").
  `job.error` carries `final_status: "error"`, `code` ∈ 15 canonical
  codes, `message`, `retryable`.
- `test_lease_grammar.py` — §9.2. Reserved namespaces (`fs.read`,
  `fs.write`, `net.fetch`, `tool.call`, `agent.delegate`, `cost.budget`).
  Vendor namespaces (`x-vendor.*`) accepted; un-prefixed unknowns
  rejected with `INVALID_REQUEST` per
  [`typescript-sdk/CONFORMANCE.md`](../../../typescript-sdk/CONFORMANCE.md)
  "Intentional deferrals".
- `test_budget_amount.py` — §9.6 amount grammar `currency:decimal`.
  Property version lives in §3 below.

Every test above asserts at the message-payload boundary, not the
transport boundary. Each module is one file; modules are split by spec
section so a failing assertion's path names the spec rule.

### 2.3. `tests/state/` — Session/Job state machine

Source under test: `src/arcp/_runtime/session.py`,
`src/arcp/_runtime/server.py`, `src/arcp/_runtime/job.py`,
`src/arcp/_runtime/lease.py`. Driven by `transport/in_memory.py`
([`02-current-audit.md`](02-current-audit.md) §2 marks `MemoryTransport`
as the right test seam).

- `test_handshake.py` — `session.hello` → `session.welcome` happy path;
  illegal `session.hello` twice on one connection produces
  `INVALID_REQUEST`. Wrong auth produces `UNAUTHENTICATED` + close.
- `test_feature_intersection.py` — Client features `{ack, subscribe}` ∩
  runtime `{heartbeat, ack, list_jobs, subscribe}` = `{ack, subscribe}`.
  Client calling `client.list_jobs()` raises `INVALID_REQUEST` because
  `list_jobs` is outside the intersection. Mirrors the TS rule in
  [`typescript-sdk/CONFORMANCE.md`](../../../typescript-sdk/CONFORMANCE.md)
  "Feature handlers MUST refuse to operate if the feature is not in the
  intersection".
- `test_job_lifecycle_states.py` — `pending → running → success`;
  `pending → running → error`; `running → cancelled`;
  `running → timed_out`. Each illegal transition (`success → running`,
  `cancelled → success`, etc.) raises the right error code per §7.3 /
  §12.
- `test_resume.py` — `last_event_seq` replay returns events with
  `event_seq > N` in order; `RESUME_WINDOW_EXPIRED` after retention
  cutoff; resume token rotates on welcome (test reads the issued token
  twice across resume and asserts inequality, matching
  [`typescript-sdk/CONFORMANCE.md`](../../../typescript-sdk/CONFORMANCE.md)
  §6.2 token-rotation row).
- `test_idempotency.py` — Same `(principal, idempotency_key)` returns
  identical `job.accepted` envelope; conflicting payload raises
  `DUPLICATE_KEY`.
- `test_subscribe_fanout_seq.py` — **The
  [`02-current-audit.md`](02-current-audit.md) §3 H-risk row.** Two
  subscriber sessions B and C, plus the submitting session A. A emits
  `job.event` seq 1..N on A's seq space. The fan-out to B uses B's
  independent seq counter; the fan-out to C uses C's. Test that:
  (1) each subscriber's per-session seq is strictly monotonic, gap-free
  (§8.3); (2) replay-with-history at `from_event_seq=0` re-issues events
  with subscriber-scoped seqs, not the submitter's original seqs;
  (3) the per-subscriber counter never collides with live emission
  after replay. This test exists specifically to fail if anyone reuses
  one shared counter across sessions, which is the regression the audit
  flags as "invisible until a subscriber resumes".
- `test_subscriber_no_cancel.py` — Subscriber B sends `job.cancel`;
  runtime returns `PERMISSION_DENIED`. Only submitter A's cancel is
  honored. §7.6 + §14 row.
- `test_heartbeat_loss.py` — `MemoryTransport` configured to drop all
  inbound from peer; runtime emits `HEARTBEAT_LOST` after 2 intervals
  (uses the event-clock pattern in §4 below — no real `asyncio.sleep`).
  Session remains until resume window elapses; jobs continue running
  server-side per §6.4 spec note "MUST NOT terminate jobs on heartbeat
  loss".
- `test_event_seq_atomicity.py` — Two concurrent jobs in one session,
  each emitting in tight loops. Assert the merged sequence is strictly
  monotonic and gap-free. This is the
  [`02-current-audit.md`](02-current-audit.md) §4 third bullet — if the
  emit primitive awaits between seq bump and dispatch, the interleaving
  is detectable in this test. Run under `pytest-randomly` with N=200
  iterations per worker (Hypothesis form in §3 below).
- `test_lease_expiry_watchdog.py` — `lease_constraints.expires_at` 100ms
  in the future (clock-injection via `validateLeaseOp(now=…)`). Wall
  passes the expiry; runtime emits `job.error{LEASE_EXPIRED,
  retryable: false}` and (if the agent attempts an op after expiry)
  surfaces `tool_result` with `LEASE_EXPIRED` first, per §13.4. No real
  `asyncio.sleep` — clock is injected.
- `test_budget_exhausted.py` — Job with `cost.budget: USD:1.00` emits
  metric `cost.fetch USD 0.70`, then `cost.fetch USD 0.40` (driving the
  counter to -0.10). Next `tool.call` returns `BUDGET_EXHAUSTED` via
  `tool_result` (§9.6 SHOULD path; §13.5 example). Negative-value
  metric is rejected and does NOT decrement the counter.
- `test_result_chunk_inline_mix.py` — `JobContext.streamResult()` then
  attempt to also set inline `result` raises `INVALID_REQUEST`
  ("MUST NOT mix" §8.4).
- `test_chunk_size_cap.py` — Chunk larger than 1 MB raises
  `INTERNAL_ERROR` per §14. Total streamed > implementation cap raises
  `INTERNAL_ERROR`.
- `test_agent_version_resolution.py` — `code-refactor` bare name with
  default `2.0.0` registered ⇒ resolves to `code-refactor@2.0.0` echoed
  in `job.accepted.payload.agent`. `code-refactor@3.0.0` ⇒
  `session.error{AGENT_VERSION_NOT_AVAILABLE}` per §13.7 (NOT
  `job.error` — no job ever existed).
- `test_list_jobs_authz.py` — Two principals P1 / P2. P1 submits job J;
  P2 calls `session.list_jobs` and J does NOT appear in the response
  (§14 "subscription-scope" / §6.6 "MUST NOT leak job existence"). The
  [`02-current-audit.md`](02-current-audit.md) §3 M-risk "getting it
  backwards leaks job existence cross-principal" — this test is the
  regression bound.

gets a corresponding test row here — file is named
`test_e2e_<transport>.py::test_example_<dirname>`.

### 2.5. `tests/conformance/` — Conformance harness

One parametrized test per row of
[`python-sdk/CONFORMANCE.md`](../../../python-sdk/CONFORMANCE.md). That
file is a stub today; Phase 8 will rewrite it to mirror
[`typescript-sdk/CONFORMANCE.md`](../../../typescript-sdk/CONFORMANCE.md)
row-for-row. The harness:

- Reads `CONFORMANCE.md`, extracts the table rows (one row =
  `(spec_§, requirement, status, location)`).
- For each row whose `Status` is "Implemented", runs a small assertion
  that calls into the cited `location` and verifies the cited spec
  rule (e.g., row "§5.1 `arcp` field, REQUIRED, MUST be `"1"`" →
  imports `arcp._version` and asserts `PROTOCOL_VERSION == "1"`).
- For "Deferred" rows, runs a tombstone test that asserts the symbol
  named in the row does NOT exist — so a future implementation can't
  silently flip a row's status without re-running the harness.

Each row's "Status: Implemented" claim is conditional on this row's
test passing in CI. The harness is the documentation-vs-code drift
detector that the TS package set lacks — Phase 8 will note the
asymmetry.

## 3. Property tests — where they pay rent

`hypothesis` strategies are defined in `tests/_strategies.py` (one
module, imported by every property test). Each `@given` declares the
strategy and the invariant explicitly.

Strategies that pay rent:

- **Envelope round-trip** (`tests/unit/envelope/test_envelope_property.py`).
  Strategy: `valid_envelopes()` builds an envelope by drawing
  `(type, payload)` from a registry of `(type → pydantic model →
  hypothesis_jsonschema strategy)` pairs. Invariant:
  `from_wire(to_wire(env)).model_dump(exclude_none=True) ==
  env.model_dump(exclude_none=True)`. `exclude_none=True` is the
  "modulo None-omission" condition the prompt names.
- **`event_seq` monotonicity**
  (`tests/state/test_event_seq_property.py`). Strategy: a list of
  `EmissionOp = Literal["emit_event", "emit_result", "emit_error"]`
  values, length 1..1000, optionally interleaved with `Literal["resume",
  "ack", "ping"]` no-op ops (none of which consume a seq per §6.4 /
  §6.5). Invariant: the emitted envelopes' `event_seq` values are
  `range(1, k+1)` exactly (strictly monotonic, gap-free, no skips on
  `ping`/`pong`/`ack`). This is the regression bound for the
  [`02-current-audit.md`](02-current-audit.md) §4 third bullet
  "event_seq atomicity under concurrent jobs" — the strategy runs the
  ops across two `asyncio.Task`s competing on one session.
- **Idempotency-key dedupe**
  (`tests/state/test_idempotency_property.py`). Strategy:
  `lists(tuples(principal=text(min_size=1, max_size=64),
  key=text(min_size=1, max_size=256),
  params=submit_payloads()), min_size=1, max_size=200)`. Invariant: for
  every (principal, key), the first submission returns a `job_id`; every
  subsequent submission with identical `params` returns the same
  `job_id`; every subsequent submission with non-identical `params`
  raises `DUPLICATE_KEY`.
- **Lease subset check**
  (`tests/state/test_lease_subset_property.py`). Strategy: a parent
  lease drawn from a fixed grammar (six reserved capabilities + glob
  patterns built from `path_segments() / glob_wildcard()`), plus a
  child lease that is either a deliberate subset, a deliberate
  superset, or random. Invariants: `is_lease_subset(child, parent)` is
  `True` iff every child pattern is matched by some parent pattern
  (§9.4); when `cost.budget` appears, child amount per currency is
  ≤ parent's remaining (§9.4 v1.1 addition); when
  `lease_constraints.expires_at` appears, child ≤ parent (§9.4 v1.1).
- **Budget arithmetic**
  (`tests/state/test_budget_property.py`). Strategy: an initial budget
  drawn from `dictionaries(currencies, decimals(places=4,
  min_value=Decimal("0.01"), max_value=Decimal("10000")))`, plus a
  list of metric ops drawn from `(name=text().filter(starts_with(
  "cost.")), value=decimals(...), unit=sampled_from(initial_budget.keys()))`.
  Invariants: counters never go positive after going negative (§9.6
  "negative metric values rejected"); `BUDGET_EXHAUSTED` fires
  exactly when the first counter reaches ≤ 0 on the next
  authority-bearing op; the `cost.budget.remaining` debounced metric is
  emitted with `value == initial - sum(decrements)`.
- **Budget amount grammar**
  (`tests/unit/messages/test_budget_amount_property.py`). Strategy:
  `from_regex(r"^[A-Za-z][A-Za-z0-9]{0,9}:[0-9]+(\.[0-9]+)?$")`.
  Invariant: `parse_budget_amount(s)` returns `(currency, Decimal)`
  with `currency == s.split(":")[0]` and `value == Decimal(s.split(":")[1])`.
  Plus a negative strategy `from_regex` over malformed inputs that
  asserts `INVALID_REQUEST` is raised.

Property tests **do NOT** pay rent for:

- **Transport happy path.** One round-trip per transport in
  `tests/e2e/` is enough. Hypothesis-fuzzing WS frame timing does not
  add coverage that loopback misses — the underlying `websockets`
  library is already tested upstream and our transport wrapper is a
  thin sender/receiver.
- **OTel span attribute generation.** Span attrs are a deterministic
  function of the envelope (`arcp.session_id`, `arcp.job_id`,
  `arcp.agent`, `arcp.lease.expires_at`, `arcp.budget.remaining` per
  §11). One sample-based test per attribute in
  `tests/unit/middleware/test_otel.py` covers the function; varying the
  input doesn't expose new branches.
- **CLI parsing.** Click is tested at its boundary with
  `CliRunner` — call signatures are flat and integer/string typed; the
  branches a property test would explore are Click's, not ours.

## 4. Cancellation / timeout test patterns

The patterns codify [`02-current-audit.md`](02-current-audit.md) §4
first bullet ("cancellation semantics") and the corresponding M-risk
rows in §3. asyncio-specific, not transliterated from TS.

- **Cancellation path.** `pytest.raises(asyncio.CancelledError)` wraps
  the awaited coroutine, not its enclosing `TaskGroup`. A
  `TaskGroup.__aexit__` that observes a `CancelledError` raised by a
  child re-raises an `ExceptionGroup[CancelledError]` (3.11+) — the test
  uses `pytest.raises(ExceptionGroup) as eg` and asserts
  `eg.value.subgroup(asyncio.CancelledError) is not None`. The TS
  idiom of `expect(...).toHaveBeenWarnedWith(...)` for cancellation
  does NOT apply; we do not use `pytest.warns` on the cancel path.

- **Timeout path.** `async with asyncio.timeout(0.05):` around the
  awaited call. SUT raises `TimeoutError`. The test asserts the
  emitted `job.error` carries `final_status: "timed_out"` and `code:
  "TIMEOUT"` per §7.3 + §12.

- **No `asyncio.sleep` races.** Tests that need elapsed time inject
  the clock. `validateLeaseOp(now=…)` is the seam for lease-expiry;
  `MemoryTransport.advance_event_clock(intervals=2)` is the seam for
  heartbeat. No test calls `asyncio.sleep(real_seconds)` for spec
  timing — only for cooperative-yield-to-scheduler (`sleep(0)`) where
  the test needs to interleave two coroutines deterministically.

- **Heartbeat-loss test pattern.** `MemoryTransport` is configured
  with `drop_inbound=True`. The runtime's session context's heartbeat
  loop reads from an injected `event_clock` (an `asyncio.Event` set
  by `advance_event_clock`) instead of `loop.call_later(seconds)`.
  The test calls `advance_event_clock(intervals=2)` and asserts the
  runtime emits `HEARTBEAT_LOST` + closes the transport, without the
  test itself ever calling `asyncio.sleep(2 * interval)`. The
  [`02-current-audit.md`](02-current-audit.md) §4 fourth bullet
  ("heartbeat coupling to TaskGroup") — heartbeat is on its own
  `asyncio.Future`, not a `TaskGroup` child, so a heartbeat-timeout
  set on that future does NOT cancel the job emit pump; the test
  asserts the job continues to make progress (its `event_seq`
  continues to advance) after `HEARTBEAT_LOST` closes the session.

## 5. CI matrix

Python: **3.11, 3.12, 3.13**. Justification per version:

- **3.11** — the floor. `asyncio.TaskGroup`, `asyncio.timeout`, and
  `ExceptionGroup` are introduced here and the
  [`02-current-audit.md`](02-current-audit.md) §4 risks all pin on
  these primitives. Matches the `requires-python = ">=3.11"` pin
  in [`03-libraries.md`](03-libraries.md) §14.
- **3.12** — PEP 695 `type` statements and the
  `asyncio.eager_task_factory` option. The
  `_runtime/server.py` fan-out path benefits from eager tasks (one
  fewer scheduler tick per emitted event) but the test plan does not
  require it; 3.12 is in the matrix because it is the default on
  Debian 12 (Trixie) and current macOS Homebrew, i.e., the version
  most consumers actually have.
- **3.13** — latest stable. Free-threaded mode is opt-in and not
  required, but the matrix includes the GIL-mode build to catch any
  3.13-specific deprecation surfacing in `pydantic` /
  `aiosqlite` / `websockets`.

3.10 is excluded — no `TaskGroup`/`timeout`/`ExceptionGroup` without a
backport, and the audit's structured-concurrency design is
load-bearing. 3.14+ is excluded until released.

OS: **Linux + macOS**. Rationale: the three deps that could differ
(`aiosqlite`, `websockets`, `asyncio`) are all portable; the macOS
runner is cheap and catches the rare BSD-vs-Linux path quirk
(`/private/var/folders` symlinks under tempdir, default umask on
SQLite-file creation). Windows is excluded — the SDK ships
POSIX-shaped tooling (`uv`, `ruff`, `pyright`) and `stdio` transport
behavior on Windows pipes is its own scope this layer does not own.

Test job sharding: `pytest-xdist` is NOT in the dev group — the
`tests/state/` layer's interleaving determinism (§3 `event_seq`
property) is fragile under parallel workers. Single-process,
`pytest-randomly` for order-shuffle, `pytest-timeout` for stuck-test
isolation. Wall-clock budget per Python version: ~3 minutes.

## 6. Minimum to hit 87 %

**Coverage floor: keep `--cov-fail-under=90`** (the value currently in
[`pyproject.toml`](../../pyproject.toml) line 114). The 87 % bound is
the floor below which the suite is failing; 90 % is achievable because
the cheap modules (envelope, messages — branches are all field
validators) carry most lines and the expensive modules' branches are
each individually small handler dispatches that the layer-3 state-machine
tests exercise pairwise (verb × negotiated-feature set).

Module-by-module budget:

- **Cheap** (≥ 95 % expected; lines + branches are validator checks):
  `_envelope.py`, `_ids.py`, `_version.py`, `_errors.py`, `extensions.py`,
  every file under `_messages/*`. Layer 2 (`tests/unit/messages/`) hits
  these directly with one parametrize per validator branch.
- **Mid** (90–95 % expected): `_runtime/lease.py`, `_runtime/pending.py`,
  `_runtime/session.py`, `_client/client.py`, `auth/bearer.py`,
  `auth/jwt.py`, `_store/eventlog.py`. Layer 3 (`tests/state/`) plus
  the property tests in §3 hit the branches; the JWKS-fetch path in
  `auth/jwt.py` uses a pytest fixture serving a static JWK
  (no network) — that branch is fully covered.
- **Expensive** (87–92 %): `_runtime/server.py` (handler dispatch table
  for ~14 inbound verbs × negotiated-feature checks × authz checks).
  Layer 3 covers every verb at least once; the rare branches (e.g.,
  `INVALID_REQUEST` for a feature outside the intersection on every
  one of the gated verbs) are exhaustively parametrized in
  `test_feature_intersection.py`.
- **Carve-outs** (excluded from `--cov-fail-under` via
  `[tool.coverage.run] omit`):
  - `src/arcp/cli.py` — exercised by a separate CLI suite using
    `click.testing.CliRunner` (one test per subcommand:
    `arcp serve`, `arcp send`, `arcp tail`, `arcp replay`). Click's
    own dispatch is not the SDK's concern. Confirmed: already omitted
    in [`pyproject.toml`](../../pyproject.toml) line 123-126.
  - `src/arcp/__main__.py` (if added by Phase 4) — `python -m arcp`
    bootstrap, behavior identical to `arcp` script entry.
  - `src/arcp/middleware/otel/__init__.py` — re-exports only.
  - `examples/**` — examples are tested by behavior (Layer 4) not by
    coverage. The example *code* counting toward the suite's
    line-coverage number would let a trivially-importable file paper
    over a missing behavior assertion.

The 90 % floor is justified because the omit list above is small (CLI,
example code, two thin re-export modules), the property tests in §3
cover all the high-branch-count files (`lease.py`, `_messages/*`), and
the conformance harness in §2.5 produces a row-level pass/fail that
makes ≥90 % the natural break point — below that, conformance rows
start un-mapping from tests.

## 7. What does NOT get tested at this layer

- **Host adapters** (Phase 5: `arcp.middleware.fastapi`,
  `arcp.middleware.asgi`, `arcp.middleware.starlette`, equivalents of
  the TS `@arcp/express`, `@arcp/fastify`, `@arcp/bun`,
  `@arcp/hono` packages). They are tested in their own packages, owned
  by Phase 5. The disposition of any adapter that
  [`05-middleware.md`](05-middleware.md) decides ships **inside**
  `arcp.middleware.*` rather than its own package — those tests
  live here under `tests/middleware/<adapter>/`. When `05-middleware.md`
  is written, this section is the place those tests get listed.
- **OTel against a real collector.** `tests/unit/middleware/test_otel.py`
  uses `opentelemetry.sdk.trace.export.InMemorySpanExporter`
  (`opentelemetry-sdk` is a dev-group dep, not runtime — confirms
  [`03-libraries.md`](03-libraries.md) §7's API-only runtime pin). No
  test starts a real Jaeger / Zipkin / OTLP receiver.
- **The spec itself.** Spec ambiguities surface as failing tests here,
  but the fix is a `spec/` issue, not a Python fixture override.
  Concretely: if §8.4 wording produces two reasonable readings of
  "MUST NOT mix inline result and result_chunk", the test does not
  ship both readings as parametrize cases; it picks one (the stricter
  reading, matching the TS implementation), the test fails until
  fixed, and the fix is an issue against `spec/docs/draft-arcp-02.1.md`.
- **`websockets`-library internals.** Frame fragmentation, ping
  control frames (the library's, not ours), TLS handshake failures.
  Each is upstream's test surface; our test surface is the envelope
  stream above it.
- **`pydantic`-library internals.** `model_dump(exclude_none=True)`
  semantics, discriminated-union dispatch correctness. Upstream's
  responsibility.
- **Performance.** No `pytest-benchmark` in the dev group.
  [`03-libraries.md`](03-libraries.md) §11 defers perf testing until
  after coverage stabilizes; revisit only if `result_chunk` validation
  shows up in production profiles, per
  [`03-libraries.md`](03-libraries.md) §1's escape hatch.
